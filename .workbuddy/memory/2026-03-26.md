## 代码质量问题修复

### AsyncStatisticsService.java (P0 BigDecimal精度问题)
- **已废弃常量修复**: `BigDecimal.ROUND_HALF_UP` → `RoundingMode.HALF_UP`
- **int截断防护**: totalRecharge 使用 `long` 累加，存入数据库时 `Math.min(totalRechargeAmount, Integer.MAX_VALUE)` 防溢出
- **除法精度提升**: ARPU/ARPPU 从保留2位小数改为4位
- **默认值设置**: arpu/arppu 在分母为0时设为 `BigDecimal.ZERO`，避免 null
- **null安全**: calculateRechargeStats 中 amount/playerId 增加 null 检查
- **废弃代码清理**: 移除 calculateRechargeStats 中多余的 QueryWrapper（不再直接查 RechargeRecord）
- **幂等性保护**: 移除 check-then-act 模式，改为 @Transactional + DuplicateKeyException 兜底（利用已有 uk_stat_date 唯一索引）；移除 @Async 避免 Spring 事务失效
- **ARPU/ARPPU精度修正**: 从4位回调为2位小数，匹配数据库 decimal(10,2) 定义
- **重复代码提取**: getDateRange() 工具方法统一时间范围计算（countNewPlayers/countActivePlayers/calculateRechargeStats/calculateRetentionRateAsync 共用）

### AntiFraudService.java (P1 输入验证 + 硬编码阈值)
- **detectLoginAbnormal**: 添加 `playerId null/<=0` 校验
- **detectResourceAbnormal**: 添加 `playerId/resourceType` 校验 + `newValue <= oldValue` 提前返回防误报
- **detectOperationFrequencyAbnormal**: 添加 `playerId/operationType null/空白` 校验
- **detectLevelAbnormal**: 添加 `playerId/oldLevel/newLevel` 校验 + `newLevel <= oldLevel` 提前返回防误报
- **handleAutoBan**: 添加 `playerId/reason` 参数校验，无效参数时记录警告日志
- **硬编码阈值提取为常量**: 所有风控阈值提取为命名 static final 常量（MULTIPLE_IP_THRESHOLD、HIGH_FREQUENCY_LOGIN_THRESHOLD、LEVEL_INCREASE_THRESHOLD、AUTO_BAN_THRESHOLD、COUNTER_EXPIRE_MS）
- **资源阈值常量化**: RESOURCE_THRESHOLDS 提取为 Collections.unmodifiableMap，消除每次调用 new HashMap
- **操作频率阈值常量化**: OPERATION_FREQUENCY_THRESHOLDS + DEFAULT_OPERATION_FREQUENCY_THRESHOLD，消除 incrementAndCheck 中每次 new HashMap

## 并发安全审计

### 审计范围
全量扫描 332 个 Java 文件，检查随机数、线程安全、竞态条件、事务一致性。

### 结果
- **随机数** ✅：全部使用 `ThreadLocalRandom.current()`，无 `new Random()`
- **线程安全** ✅：无静态可变状态；ConcurrentHashMap/volatile 使用正确；111+ HashMap/ArrayList 均为局部变量
- **竞态条件** ⚠️：发现 3 类 P1 + 1 类 P2 + 1 类 P3 问题
  - P1: 拍卖行 TOCTOU（可重复购买）、宗门BOSS血量丢失、宗门成员计数不一致
  - P2: 灵石/经验 30+ 处读-改-写非原子
  - P3: 9个 @Scheduled 定时任务共用默认单线程池
- **事务** ⚠️：所有写操作有 @Transactional，但默认 REPEATABLE READ 不防行级竞态

### 修复方案（全量执行）
- **P1 拍卖行 TOCTOU**：`AuctionItemMapper` 新增 `claimAuctionItem`/`cancelAuctionItem`/`expireAuctionItem` 三个 `@Update` 原子条件更新；`AuctionService` 的 `buyItem()`/`cancelAuction()`/`processExpiredAuctions()` 全部改用原子SQL，返回 0 行时抛异常
- **P1 宗门BOSS血量**：`GuildBossMapper.atomicDamage()` 使用 `GREATEST(0, current_health - #{damage})` + CASE 状态判断；`challengeBoss()` 先原子更新再重查
- **P1 宗门成员计数/资金/贡献**：`GuildMapper` 新增 `incrementMemberCount`/`decrementMemberCount`/`addGuildFunds`；`GuildMemberMapper` 新增 `addContribution`；`GuildService.handleApplication()`/`leaveGuild()`/`donate()` 全部改用原子SQL
- **P2 乐观锁**：`PlayerProfile`/`Guild`/`GuildBoss`/`GuildBossChallenge` 4个Entity加 `@Version Integer version` 字段；`MybatisPlusConfig` 注册 `OptimisticLockerInnerInterceptor`
- **P3 DegradeConfig**：`getStrategies()` 返回 `Collections.unmodifiableMap()` 视图
- **SQL迁移脚本**：`docs/sql/add-optimistic-lock-columns.sql`（4张表加 version 列）
