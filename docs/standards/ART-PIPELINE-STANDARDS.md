## 1. 资产预算规范

### 1.1 UI元素预算表

所有UI元素必须在生产前通过本规范验证。

#### 界面类型与预算

| 界面类型 | 最大DOM节点数 | CSS规则数上限 | 图片资源数 | 加载时间(ms) | 说明 |
|---------|-------------|-----------|---------|-----------|------|
| 登录页 | 50 | 200 | 5 | 800 | 快速首屏，尽量简洁 |
| 主游戏界面 | 150 | 500 | 15 | 1500 | 核心交互界面 |
| 战斗页面 | 100 | 300 | 10 | 1200 | 实时交互，需要流畅 |
| 背包页面 | 200 | 400 | 20 | 1500 | 列表密集，允许分页 |
| 任务页面 | 120 | 350 | 12 | 1300 | 中等复杂度 |
| 排行榜 | 80 | 250 | 8 | 1000 | 数据表单为主 |

#### 动画性能预算

| 动画类型 | 最大并发数 | 帧率目标 | 单个持续时间(ms) | GPU成本 |
|---------|---------|--------|---------------|--------|
| 淡入淡出 | 无限制 | 60fps | 300-500 | 低 |
| 滑动/移动 | 10 | 60fps | 400-600 | 低 |
| 缩放变换 | 10 | 60fps | 300-400 | 低 |
| 伤害飘字 | 20 | 60fps | 1000-1200 | 中 |
| 特效粒子 | 5 | 30fps | 1000-2000 | 高 |

**关键规则**：
- 伤害飘字最大并发数 = 20个，超出时丢弃最新飘字
- 所有动画使用 `transform` 和 `opacity`，不要使用 `left/top` 属性（触发重排）
- 禁止使用 `box-shadow` 在动画中更新（GPU成本极高）

### 1.2 图片资源预算

所有图片必须按以下规范压缩和导入。

#### 图片类型与规范

| 类型 | 最大分辨率 | 文件格式 | 压缩率 | 用途示例 |
|-----|---------|--------|------|--------|
| UI背景 | 1920×1080 | WebP (首选) / PNG | 80%+ | 登录背景、主界面 |
| 按钮贴图 | 256×256 | WebP / PNG | 70%+ | 各类按钮 |
| 角色头像 | 128×128 | WebP / PNG | 70%+ | 玩家/怪物头像 |
| 小图标 | 64×64 | SVG (首选) / PNG | 85%+ | UI图标 |
| 装备/物品 | 256×256 | WebP / PNG | 75%+ | 物品栏显示 |
| 宠物立绘 | 512×512 | WebP / PNG | 75%+ | 宠物详情页 |

**导入流程**：
```markdown
1. 源文件导入 → 高质量原始文件 (不压缩)
2. 格式转换 → WebP (优先) 或 PNG
3. 自动压缩 → 使用工具链自动压缩至目标大小
4. 版本控制 → 记录原始文件和最终大小
```

#### 建议工具链

```bash
# WebP转换
cwebp -q 80 input.png -o output.webp

# PNG优化
optipng -o2 input.png

# 批量处理
for f in *.png; do cwebp -q 80 "$f" -o "${f%.png}.webp"; done
```

### 1.3 CSS与样式表预算

| 指标 | 限制 | 说明 |
|-----|-----|------|
| 总样式表大小 | <100KB | gzip后 |
| 单个文件大小 | <50KB | CSS文件 |
| CSS选择器数量 | <2000 | 整个项目 |
| 特异性最大值 | 0,5,0 | 避免过度嵌套 |
| 媒体查询断点数 | <8 | 响应式设计 |

**关键规则**：
- 禁止使用 `!important`（除必要情况）
- 避免 `*` 通配符选择器
- 使用CSS变量替代重复色值（已在 `modern-style.css` 实现）
- 动画使用 `will-change` 提前优化

## 2. 质量检查清单

### 2.1 UI视觉检查

在进入生产环节前，美术资产必须通过以下检查：

**[ ] 视觉完整性**
- [ ] 所有元素在目标分辨率下完整显示
- [ ] 无明显的截断或重叠
- [ ] 文字清晰可读（最小12px）
- [ ] 对比度符合WCAG AA标准（最小4.5:1）

**[ ] 颜色一致性**
- [ ] 使用规范中定义的色值
- [ ] 同类型元素颜色统一
- [ ] 过渡色平滑自然
- [ ] 暗色模式适配（如适用）

**[ ] 交互反馈**
- [ ] 按钮有hover状态
- [ ] 活跃元素有视觉区分
- [ ] 加载状态有动画反馈
- [ ] 成功/失败状态明确显示

**[ ] 响应式适配**
- [ ] PC端 (1920×1080) ✓
- [ ] 平板端 (768×1024) ✓
- [ ] 手机端 (375×667) ✓
- [ ] 字体和间距合理缩放

### 2.2 性能检查

**[ ] 资源优化**
- [ ] 所有图片使用WebP格式（必要时PNG备用）
- [ ] 图片分辨率不超过规范限制
- [ ] 无冗余CSS或重复定义
- [ ] 使用CSS Sprites或图标字体合并小图标

**[ ] 动画性能**
- [ ] 使用Chrome DevTools Performance标签测试
- [ ] 帧率稳定在60fps（或目标值）
- [ ] 无持续的内存泄漏
- [ ] GPU用量在预算内

**[ ] 加载性能**
- [ ] 首屏内容加载<1000ms
- [ ] LCP (最大内容绘制) <2.5s
- [ ] CLS (累积布局移位) <0.1

### 3.3 HTML导入清单

在HTML中导入资产时必须验证：

```html
<!-- ✓ 正确示例 -->
<img src="/images/ui/backgrounds/bg-login-1920x1080-v1.webp" 
     alt="登录背景"
     loading="lazy"
     width="1920" 
     height="1080">

<!-- ✗ 错误示例 - 无alt、无尺寸、无loading属性 -->
<img src="/images/bg-login.png">
```

**导入规则**：
- 总是指定 `width` 和 `height` (防止布局移位)
- 使用 `alt` 属性（无障碍）
- 大图片使用 `loading="lazy"` (延迟加载)
- 优先使用相对路径 `/images/...`

## 5. 性能分类

### 5.1 特效性能分级

根据计算成本和并发限制，将游戏中的特效分为三级：

#### Level 1 - 低成本特效（无限并发）
- 简单淡入淡出
- 文字飘字
- 按钮hover效果
- 边框渐变
- **GPU成本**: <1ms
- **示例**: 伤害数字、UI按钮动画

#### Level 2 - 中等特效（最多10-20并发）
- 移动/滑动动画
- 旋转效果
- 阴影变化
- 缩放变换
- **GPU成本**: 1-3ms
- **示例**: 页面切换、菜单展开、血条更新

#### Level 3 - 高成本特效（最多5并发，移动端禁用）
- 复杂粒子效果
- 多层动画组合
- 滤镜效果 (blur, shadow)
- 大型元素缩放
- **GPU成本**: 3-10ms
- **示例**: 战斗爆炸效果、技能特效

### 5.2 性能调试指标

**Chrome DevTools 性能标准**:

```

LCP (Largest Contentful Paint):    < 2.5s
CLS (Cumulative Layout Shift):     < 0.1
FID (First Input Delay):           < 100ms
```

## 7. 常见问题与解决方案

### Q1: 图片质量和大小无法平衡？
**解决方案**: 
- 对摄影/照片类使用有损压缩 (WebP 75-85质量)
- 对图形/UI类使用无损压缩 (PNG 或 WebP 90+质量)
- 使用 `srcset` 为不同设备加载不同尺寸
- 考虑使用SVG替代简单的图形

### Q2: 特效超过帧率预算？
**解决方案**:
- 降低并发数量限制
- 使用更简单的动画 (淡入淡出替代缩放)
- 在移动端禁用高成本特效
- 使用requestAnimationFrame优化动画循环

### Q3: CSS选择器过多影响性能？
**解决方案**:
- 使用CSS预处理器 (SCSS/LESS) 组织代码
- 移除未使用的CSS (PurgeCSS 工具)
- 使用BEM命名法简化选择器
- 按功能模块拆分CSS文件
