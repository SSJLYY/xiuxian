## 发现的 Bug 列表

### 1. CultivateUI.js - 内存泄漏风险（1 处）🟠 P1

**问题描述**: 定义了 `stopAutoRefresh()` 方法，但从未在任何地方调用；缺少 `destroy()` 方法

**问题代码**:
```javascript
// 定义了停止方法
stopAutoRefresh() {
    if (this.cultivateTimer) {
        clearInterval(this.cultivateTimer);
        this.cultivateTimer = null;
    }
}
// ❌ 但是从未调用过！
// ❌ 也没有 destroy() 方法
```

**影响**:
- 用户离开修炼页面后，定时器继续运行
- 每 1 秒执行一次 API 请求（`getCultivateInfo()`）
- 长时间使用后可能导致内存泄漏
- 控制台可能出现"组件已卸载但仍在更新状态"的警告

**修复方案**:
```javascript
// 添加 destroy() 方法
destroy() {
    this.stopAutoRefresh();
    this.elements = null;
    this.cultivateInfo = null;
    this.isInitialized = false;
}
```

**修复后**:
- ✅ 添加了 `destroy()` 方法
- ✅ 正确清理定时器
- ✅ 释放 DOM 引用
- ✅ 重置初始化状态

### 2. CombatUI.js - 生命周期管理不完整（1 处）🟡 P2

**问题描述**: 有 `stopAutoRefresh()` 方法并在 `endCombat()` 中调用，但缺少统一的 `destroy()` 方法

**现状分析**:
```javascript
// ✅ 好的：在 endCombat 中清理了定时器
endCombat(combatResult = null) {
    clearInterval(this.combatTimer);
    // 显示结果...
}

// ✅ 好的：定义了 stopAutoRefresh
stopAutoRefresh() {
    if (this.combatTimer) {
        clearInterval(this.combatTimer);
        this.combatTimer = null;
    }
}

// ❌ 但是：缺少 destroy() 方法
```

**影响**:
- 虽然战斗结束时会清理定时器，但如果用户在战斗中离开页面，定时器可能继续运行
- 没有统一的销毁接口，不利于框架级的生命周期管理

**修复方案**:
```javascript
// 添加 destroy() 方法
destroy() {
    this.stopAutoRefresh();
    this.elements = null;
    this.currentCombat = null;
    this.isInitialized = false;
}
```

**修复后**:
- ✅ 添加了 `destroy()` 方法
- ✅ 提供统一的销毁接口
- ✅ 可以在页面切换时主动调用
