## 发现的 Bug 列表

### 1. InventoryService.js - 数据验证缺失（2 处）🟠 P1 已修复

**问题描述**: 出售和丢弃物品时没有验证参数有效性

**问题代码**:
```javascript
// ❌ Bug 1: sellItem 没有验证参数
async sellItem(itemId, quantity = 1) {
    try {
        const response = await gameAPI.sellItem(itemId, quantity);
        // 如果 itemId 为 null 或 0，会怎样？
        // 如果 quantity 为负数或 0，会怎样？
    }
}

// ❌ Bug 2: discardItem 没有验证 itemId 和 quantity
async discardItem(itemId, quantity = 1) {
    if (!confirm('确定要丢弃这个物品吗？')) {
        return;
    }
    // 直接调用 API，没有验证参数
}
```

**影响**:
- 如果传入 `itemId = null` 或 `itemId = 0`，可能导致：
  - 后端空指针异常
  - 误操作其他物品
  - 数据库查询错误
- 如果传入 `quantity <= 0`，可能导致：
  - 逻辑错误（出售 0 个物品）
  - 后端验证失败
  - 用户体验差

**修复方案**:
```javascript
// ✅ 修复后
async sellItem(itemId, quantity = 1) {
    // 参数验证
    if (!itemId || quantity < 1) {
        toast.error('参数错误');
        return;
    }
    
    try {
        const response = await gameAPI.sellItem(itemId, quantity);
        // ...
    }
}

// ✅ 修复后
async discardItem(itemId, quantity = 1) {
    // 参数验证
    if (!itemId || quantity < 1) {
        toast.error('参数错误');
        return;
    }
    
    if (!confirm('确定要丢弃这个物品吗？此操作不可恢复!')) {
        return;
    }
    // ...
}
```

**修复后效果**:
- ✅ itemId 为 null/0 时立即返回错误提示
- ✅ quantity < 1 时立即返回错误提示
- ✅ 避免无效请求发送到后端
- ✅ 提升用户体验和系统安全性
